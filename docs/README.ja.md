## なぜ RulAI が必要？

コーディングエージェントは強力ですが、実際に使っていてこんな経験はありませんか：

- バグが堂々巡り — A を直したら B が壊れる
- 指示を鵜呑みにして実行 — 結果が期待と大きくかけ離れる
- コンテキストが失われる — 同じ失敗を何度も繰り返す
- 能動的なデバッグ戦略がない — 当てずっぽう頼み

**RulAI** は自己進化するインタラクションルールをワンコマンドで初期化し、AI との協業を回を重ねるごとにスムーズにします。

## インストール

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/CNJ-Devs/rulai/master/install.sh)"
```

CLI は `~/.local/bin/rulai` にインストールされます。このディレクトリが `PATH` に含まれていない場合、インストーラーが追加を案内します。

## 使い方

```bash
cd your-project
rulai setup      # 対話式ルール初期化
```

### 全コマンド

| コマンド | 説明 |
|----------|------|
| `rulai setup` | 対話式でインタラクションルールを初期化・再設定 |
| `rulai status` | 現在のプロジェクト設定とファイル状態を表示 |
| `rulai update` | CLI を最新バージョンに自己更新 |
| `rulai version` | バージョンを表示し、更新を確認 |
| `rulai help` | ヘルプを表示 |

## ルール一覧

| # | ルール | トリガー | 動作 |
|---|--------|----------|------|
| 1 | 曖昧な指示を拒否 | 指示が曖昧 | 確認を求める、黙って推測しない |
| 2 | デバッグエスカレーション | バグが 1〜2 回で直らない | console.log の追加を提案 |
| 3 | エラーサーキットブレーカー | 同じアプローチで 3 回以上 | 停止 → 代替案を提示 → ユーザーの選択後に実行 |
| 4 | 修正後の振り返り | バグ修正後 | 「どう聞けばよかったか」をまとめる |
| 5 | 経験の記録 | 振り返り後 | learned lessons ファイルに記録 |
| 6 | 並行探索 | 新機能の着手時 | アプローチを提案（クロスエージェントオプション含む） |
| 7 | ドキュメント先行 | 複数ファイルにまたがる新機能 | 先に implementation plan を作成 |
